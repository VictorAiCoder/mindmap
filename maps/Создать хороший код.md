## 1. Читаемость — главный приоритет

> «Код читают в 10 раз чаще, чем пишут» — Роберт Мартин

### Размер файлов
- **Максимум 300 строк** на файл
- **Максимум 20-30 строк** на функцию/метод
- **Максимум 3 уровня** вложенности

### Именование

```typescript
// ❌ Плохо
const d = 86400
const ul = getUl()
const flag = true

// ✅ Хорошо
const SECONDS_IN_DAY = 86400
const activeUsersList = getActiveUsers()
const isModalVisible = true
```

#### Конвенции именования JS/TS

| Что | Стиль | Пример |
|---|---|---|
| Переменные, функции | camelCase | `getUserData()` |
| Константы | UPPER_SNAKE | `MAX_RETRY_COUNT` |
| Классы, интерфейсы, типы | PascalCase | `UserService`, `IUserRepo` |
| Булевы переменные | is/has/can/should | `isLoading`, `hasAccess` |
| Обработчики событий | handle/on | `handleClick`, `onSubmit` |
| Приватные поля | _ префикс | `_internalState` |

### Функции
- Делают **одну вещь**
- Название — **глагол**
- **Не более 3 параметров**

```typescript
// ❌ Плохо — функция делает всё сразу
function processUser(name: string, age: number, email: string, 
                     role: string, sendEmail: boolean) {
  // валидация + создание + отправка письма + логирование
}

// ✅ Хорошо — разделяем ответственность
function validateUserData(data: CreateUserDTO): ValidationResult { ... }
function createUser(data: CreateUserDTO): User { ... }
function sendWelcomeEmail(user: User): void { ... }
```

## 2. Специфика TypeScript

### Строгая типизация — всегда

```typescript
// ❌ Плохо
const getUser = (id: any): any => { ... }

// ✅ Хорошо
interface User {
  id: number
  name: string
  email: string
}

const getUser = (id: number): Promise<User | null> => { ... }
```

### Используй утилитарные типы

```typescript
// Вместо дублирования
type UserPreview = Pick<User, 'id' | 'name'>
type UserUpdate = Partial<User>
type RequiredUser = Required<User>
type ReadonlyUser = Readonly<User>
```

### Перечисления и union types

```typescript
// ❌ Магические строки
if (status === 'active') { ... }

// ✅ Типизированные значения
type UserStatus = 'active' | 'inactive' | 'banned'

// или enum для сложных случаев
enum OrderStatus {
  Pending = 'pending',
  Confirmed = 'confirmed',
  Shipped = 'shipped',
}
```

### Избегай `as` — используй type guards

```typescript
// ❌ Опасное приведение
const user = data as User

// ✅ Type guard
function isUser(data: unknown): data is User {
  return (
    typeof data === 'object' &&
    data !== null &&
    'id' in data &&
    'name' in data
  )
}

if (isUser(data)) {
  console.log(data.name) // TypeScript знает тип
}
```

## 3. Специфика Vue 3 + Composition API

### Структура компонента

```vue
<script setup lang="ts">
// 1. Импорты
import { ref, computed, onMounted } from 'vue'
import { useUserStore } from '@/stores/user'
import UserCard from '@/components/UserCard.vue'

// 2. Типы/интерфейсы (если локальные)
interface Props {
  userId: number
  isEditable?: boolean
}

// 3. Props & Emits
const props = withDefaults(defineProps<Props>(), {
  isEditable: false,
})

const emit = defineEmits<{
  save: [user: User]
  cancel: []
}>()

// 4. Composables / Store
const userStore = useUserStore()
const { showNotification } = useNotification()

// 5. Реактивное состояние
const isLoading = ref(false)
const searchQuery = ref('')

// 6. Computed
const filteredUsers = computed(() =>
  userStore.users.filter(u =>
    u.name.toLowerCase().includes(searchQuery.value.toLowerCase())
  )
)

// 7. Методы
function handleSave(user: User): void {
  emit('save', user)
}

// 8. Lifecycle
onMounted(() => {
  userStore.fetchUsers()
})
</script>

<template>
  <!-- Максимум 50 строк шаблона -->
</template>

<style scoped>
  /* Только scoped стили */
</style>
```

### Декомпозиция компонентов

```
# ❌ Один гигантский компонент
UserDashboard.vue (800 строк)

# ✅ Разделяй на мелкие
UserDashboard.vue          → layout + координация
├── UserSearchBar.vue      → поиск
├── UserList.vue           → список
│   └── UserCard.vue       → карточка
├── UserDetailsPanel.vue   → детали
└── UserStatsWidget.vue    → статистика
```

### Composables — выноси логику из компонентов

```typescript
// composables/useSearch.ts
import { ref, computed, type Ref } from 'vue'

export function useSearch<T>(
  items: Ref<T[]>,
  searchField: keyof T
) {
  const searchQuery = ref('')

  const filteredItems = computed(() => {
    if (!searchQuery.value) return items.value
    
    return items.value.filter(item =>
      String(item[searchField])
        .toLowerCase()
        .includes(searchQuery.value.toLowerCase())
    )
  })

  function resetSearch(): void {
    searchQuery.value = ''
  }

  return {
    searchQuery,
    filteredItems,
    resetSearch,
  }
}
```

```vue
<!-- Использование в компоненте — чисто и кратко -->
<script setup lang="ts">
const { searchQuery, filteredItems, resetSearch } = useSearch(users, 'name')
</script>
```

## 5. Паттерны проектирования в JS/TS/Vue

### Strategy — переключение поведения

```typescript
// strategies/sortStrategies.ts
type SortStrategy<T> = (a: T, b: T) => number

const sortByName: SortStrategy<User> = (a, b) =>
  a.name.localeCompare(b.name)

const sortByDate: SortStrategy<User> = (a, b) =>
  new Date(b.createdAt).getTime() - new Date(a.createdAt).getTime()

const sortStrategies: Record<string, SortStrategy<User>> = {
  name: sortByName,
  date: sortByDate,
}

// Использование
const sorted = users.sort(sortStrategies[currentSort])
```

### Repository — изоляция API

```typescript
// services/api/userApi.ts
class UserApi {
  private http: HttpClient

  constructor(http: HttpClient) {
    this.http = http
  }

  async getAll(): Promise<User[]> {
    const { data } = await this.http.get<UserDTO[]>('/users')
    return data.map(UserMapper.toDomain)
  }

  async getById(id: number): Promise<User> {
    const { data } = await this.http.get<UserDTO>(`/users/${id}`)
    return UserMapper.toDomain(data)
  }
}
```

### Observer — через Vue event bus или mitt

```typescript
// eventBus.ts
import mitt from 'mitt'

type Events = {
  'user:created': User
  'notification:show': { message: string; type: 'success' | 'error' }
}

export const eventBus = mitt<Events>()

// Публикация
eventBus.emit('user:created', newUser)

// Подписка
eventBus.on('user:created', (user) => { ... })
```

## 6. Правила Code Review

### Чеклист для автора PR

```markdown
- [ ] Нет файлов > 300 строк
- [ ] Нет функций > 30 строк
- [ ] TypeScript — без `any`
- [ ] Компоненты Vue < 200 строк (template + script)
- [ ] Новая логика вынесена в composable/service
- [ ] Нет дублирования кода
- [ ] Понятные имена переменных и функций
- [ ] Нет закомментированного кода
- [ ] console.log удалены
```

### Чеклист для ревьюера

```markdown
- [ ] Понимаю ли я этот код без объяснений автора?
- [ ] Нет ли скрытых побочных эффектов?
- [ ] Правильно ли обрабатываются граничные случаи?
- [ ] Не нарушает ли код существующую архитектуру?
- [ ] Можно ли упростить?
```

### Культура ревью

```
❌ "Это неправильно"
✅ "Рассмотри вариант с computed вместо watch — 
    будет реактивнее и меньше побочных эффектов"

❌ "Переделай"
✅ "Предлагаю вынести эту логику в useSearch composable,
    потому что она повторяется в 3 компонентах"
```

## 7. Git Flow

### Ветки

```
main              ← продакшн, всегда стабилен
├── develop       ← текущая разработка
│   ├── feature/user-auth      ← новая фича
│   ├── feature/order-table    ← новая фича
│   └── fix/login-redirect     ← баг-фикс
└── hotfix/critical-bug        ← срочный фикс в продакшн
```

### Коммиты — Conventional Commits

```
feat(auth): добавить авторизацию через Google
fix(cart): исправить расчёт скидки при пустой корзине
refactor(user): вынести валидацию в отдельный composable
chore(deps): обновить Vue до 3.4
docs(readme): добавить инструкцию по запуску
```

### Правила

```
1. Один PR = одна задача
2. PR не больше 400 строк изменений
3. Ветка живёт не дольше 2-3 дней
4. Merge только после approve ревьюера
5. Перед merge — rebase на актуальный develop
```
