# 📄 КРАТКОЕ ТЗ (TL;DR) — «Садовод v1»

## Что это
Веб-приложение на Vue 3 + TypeScript для планирования садового участка: рисуем контур участка, расставляем многолетние посадки, переключаем тематические слои.

## Ключевые функции v1
1. **Модель участка** — задать форму и размеры участка (прямоугольник/полигон).
2. **Многолетние посадки** — добавлять на карту объекты (деревья, кусты, грядки-многолетники) с базовыми атрибутами.
3. **Слои** — переключатель: рельеф, посадки, инженерка (в v1 слои существуют, но наполнение минимальное — см. подробное ТЗ).
4. **3 типа визуализации** — 2D top-view, схема-иконки, список/таблица.
5. **Локальное сохранение** — localStorage (без бэкенда).

## Что НЕ входит в v1 (на v2+)
- ❌ Соцсеть садоводов
- ❌ Сессии-теплицы, закрытый грунт
- ❌ База плодовых культур / зелени для теплицы
- ❌ Однолетники и севооборот
- ❌ Мульти-пользователь, облачная синхронизация
- ❌ Расширенные сорта, «философия сессий»

## Стек
Vue 3 (Composition API) + TypeScript + Vite + Pinia + Konva.js (или SVG) для 2D-холста.

## Срок
2 недели. ⚠️ Реалистично при full-time работе одного разработчика.

# 📘 ПОДРОБНОЕ ТЗ — «Садовод v1»

## 1. Цель продукта
Дать садоводу инструмент для цифрового плана участка с многолетними посадками. В v1 — открытый грунт, упрощённый справочник культур, локальное хранение. Архитектура готовится к расширению.

## 4. Доменные модели (TypeScript)

```ts
// entities/plot/model.ts
export interface Plot {
  id: string;
  name: string;
  shape: 'rectangle' | 'polygon';
  // для rectangle — width/height в метрах; для polygon — вершины
  dimensions: { width: number; height: number } | null;
  polygon: Array<{ x: number; y: number }> | null;
  createdAt: string;
  updatedAt: string;
  schemaVersion: 1; // для миграций в v2
}

// entities/planting/model.ts
export interface Planting {
  id: string;
  plotId: string;
  cropId: string;           // ссылка на справочник
  position: { x: number; y: number }; // в метрах от угла участка
  radius: number;           // крона / зона, метры
  plantedAt: string | null;
  note: string;
  layerId: LayerId;         // к какому слою относится (по умолчанию 'plantings')
}

// entities/layer/model.ts
export type LayerId = 'relief' | 'plantings' | 'engineering';
export interface Layer {
  id: LayerId;
  title: string;
  visible: boolean;
  order: number;
}

// entities/crop/model.ts — упрощённый «сорт»
export interface Crop {
  id: string;
  name: string;             // «Яблоня», «Смородина чёрная»
  kind: 'tree' | 'shrub' | 'perennial-bed';
  defaultRadius: number;    // м
  icon: string;             // emoji или ключ иконки
  color: string;            // hex для отображения
}
```

## 5. Функциональные требования

### 5.1. Участок (Plot)
- Создание одного участка (в v1 — **один активный участок**, мульти — v2).
- Форма: прямоугольник (ширина/высота в метрах) **ИЛИ** полигон (клики по канве для вершин).
- Редактирование размеров и имени.
- Удаление с подтверждением.

### 5.2. Посадки (Plantings)
- Добавление: выбор культуры из справочника → клик на канве → объект появляется.
- Перетаскивание объекта по канве (drag).
- Изменение радиуса (через handle или инпут в панели свойств).
- Редактирование атрибутов: дата посадки, заметка.
- Удаление.
- Ограничение: объект не может выйти за пределы участка (валидация при drop).

### 5.3. Справочник культур (Crop)
- **Захардкоженный seed-список на 10–15 позиций**: яблоня, груша, вишня, слива, смородина, крыжовник, малина, клубника, ревень, спаржа, хоста, пион, роза, хвойник, живая изгородь.
- Возможность пользователю **добавить свою** культуру (имя, вид, цвет, радиус). Без иконок-картинок в v1 — только emoji или цветной круг.
- ⚠️ Без сложной агротехники, зон зимостойкости, совместимости — это v2.

### 5.4. Слои (Layers)
В v1 есть три слоя, но реально наполнен только `plantings`:
- **`plantings`** — посадки (основной рабочий слой v1).
- **`relief`** — слой-заглушка: возможность добавить «заметку рельефа» (точка + текст: «склон», «низина»). Без горизонталей.
- **`engineering`** — слой-заглушка: возможность добавить «точку инженерки» (точка + текст: «колодец», «кран», «розетка»). Без линий-коммуникаций — это v2.

Переключатель видимости каждого слоя (чекбоксы).

### 5.5. Визуализации (3 типа для v1)
1. **Top-view 2D (канва)** — основной режим, Konva.js. Участок + посадки как круги с цветом/emoji.
2. **Schema-view** — та же канва, но без масштаба: объекты как крупные иконки на сетке, для «схематичного» понимания.
3. **List-view** — таблица всех посадок: культура, координаты, радиус, дата, заметка, слой. Сортировка по колонкам.

Переключатель — таб-бар сверху.

### 5.6. Хранение
- Автосохранение в `localStorage` при каждом изменении (debounce 300 мс).
- Экспорт/импорт JSON (кнопки) — **обязательно**, это страховка для пользователя и упрощает отладку.
- Версия схемы `schemaVersion: 1` в каждом объекте — чтобы в v2 написать миграцию.

## 6. Нефункциональные требования
- Адаптив: desktop-first, минимум 1280×800. Мобайл — v2.
- Производительность: плавная работа до 200 посадок на канве.
- i18n: тексты вынести в `shared/lib/i18n` (в v1 только ru, но через словарь).
- Доступность: базовая семантика, фокус-кольца, клавиша Esc закрывает модалки.

## 10. Риски и мои замечания 🧠

1. **⚠️ Polygon-редактор — самая сложная часть.** Если поджимает время — оставить только прямоугольник в v1, полигон перенести в v1.1.
2. **⚠️ Konva vs SVG.** Я предлагаю Konva (проще с трансформерами и drag), но если разработчик уверенно владеет SVG — можно SVG, будет легче с a11y.
3. **⚠️ «Три визуализации» за две недели** — Schema-view и Top-view почти дублируют друг друга. Предлагаю Schema делать как простой режим Top-view с флагом `schematic: true` (без масштаба, крупные иконки) — сэкономим 1–2 дня.
4. **localStorage имеет лимит ~5 МБ** — для v1 хватит с запасом, но для v2 сразу планируем IndexedDB.
